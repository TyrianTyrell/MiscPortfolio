# 7-1 Software Development Lifecycle Deliverables.
This one's not really code. It's a classwork submission. It's meant to be about user input regarding coding, but...

I digress. Essentially, the best way to implement what a user wants into a project is to ask, for starters. The best person to tell you what the client wants is the client themselves. This is what user stories are meant for, so that the users can tell you what they want.

I was already pretty much implementing a couple of Agile strategies before this class. If I, or the client, wanted to change how something worked I would just change course without strictly sticking to the prior plan. The essential end goal remained as it was, but if I didn't need to scrap everything I just kept on keeping on. To that end, I basically spoke to the clients constantly. I also kept the metaphorical pieces from being "glued together" until I was absolutely sure everything was where I or the client wanted it.

To be a good team member, you need to talk to your team members, and the client. You also need to keep up to date on what parts of the project need to be done, and how the team has decided to go about them- which can be done by attending meetings or sending emails.
